Prompt in · MP4 out

A studio-framed demo from one sentence.

jitters drives a real browser from a prompt, records page pixels, then composites a window, background, synthetic cursor, zooms, ripples, and motion blur. Capture once. Restyle forever.

open https://example.com
click “More information…”
hold for zoom-out
export 1920×1080

Start here

From a clone of the repo, after pnpm install and pnpm build:

jitters "Open https://example.com and click 'More information...'" --url https://example.com

Stdout is JSON pointing at the MP4 and the project folder. Logs go to stderr so agents can parse the result.

{ "status": "done", "out": "/abs/demo.mp4", "project": "/abs/demo.jitters", "durationMs": 12345, "steps": [] }
Tutorial Capture your first framed demo end to end. How-to Restyle, switch providers, and set defaults. Reference CLI flags, style.json, config.toml, stdout. Explanation Why capture and render are two different jobs.

What you need

  • Node.js, with the package built (pnpm build).
  • agent-browser on PATH, with Chrome installed via agent-browser install.
  • ffmpeg on PATH.
  • A provider API key in the environment — never in config, video, or stdout. TypeSafe is the default (TYPESAFE_API_KEY).

--help works with none of those. Capture checks the selected provider key, agent-browser, and ffmpeg, then names whichever is missing. Render only needs ffmpeg.
